# OC OS — «своя система» с нуля

Учебная x86_64-операционная система: **свой загрузчик** (MBR + stage2, без
GRUB/Limine) и **ядро на C** (без libc, freestanding), работающее в Long Mode.
Грузится с USB-флешки как обычная BIOS-загрузка с диска.

**Интерфейс полностью на русском языке**: шелл, справка, сообщения об
ошибках и паника — по-русски; есть русская раскладка клавиатуры (Ctrl+Space)
и кириллический шрифт (включая «№»). Технические маркировки загрузчика (до
запуска ядра) — латиницей: текстовый экран BIOS не имеет кириллицы.

```
BIOS → MBR (stage1) → stage2 (E820, A20, VBE, Long Mode) → ядро OC
                                                    RDI = bootinfo (0x7000)
```

## 🛡️ Защита вашей основной системы

OC спроектирована так, чтобы **не иметь возможности** навредить вашему
диску, и это проверяется тестами:

1. **Ядро физически не умеет писать на диски** — в нём нет дисковых
   драйверов вообще, а смоук-тест («Тест 5: защита вашей ОС») следит за
   портами ATA/IDE/флоппи/DMA на протяжении ВСЕЙ сессии и падает, если
   ОС хоть раз туда напишет. Загрузчик читает диск только через BIOS и
   только с того носителя, с которого загрузился.
2. **Скрипт записи `scripts/flash.sh` не даст `dd`-нуть не туда** — он
   отказывается писать:
   * на разделы (`/dev/sdb1`) — только целый диск (`/dev/sdb`);
   * на диск с любыми примонтированными файловыми системами;
   * на **системный диск** (тот, где смонтированы `/`, `/boot`, `/home`…);
   * на не-USB накопители и диски больше 64 ГБ (похожие на винчестер);
   * без двойного подтверждения (повторное ввод имени устройства + `YES`).

### Установщик (Windows)

1. Скачайте `OC-Setup.exe` (кнопка «Download raw file») и запустите.
   Windows может показать предупреждение о неподписанной программе —
   «Подробнее» → «Всё равно запустить».
2. Программа сама запросит права администратора — согласитесь (нужно, чтобы
   записать образ на флешку).
3. Выберите свою флешку в списке → «Установить». Готово!

Установщик защищает вашу основную систему, как и скрипт `flash.sh`:
системный диск (и весь диск с Windows) вообще не показывается, большие
диски скрыты (галочка «показать все диски» — на свой страх и риск),
перед записью — двойное подтверждение. Если Windows после установки
предложит «отформатировать флешку» — нажмите «Отмена»: там наша система.

### Загрузка: UEFI и Legacy BIOS — обе!

Образ умеет грузиться **обоими способами**, так что менять настройки BIOS
не нужно:

* **UEFI** (все современные ПК, например HP без Legacy-режима): прошивка
  сама находит `\EFI\BOOT\BOOTX64.EFI` на флешке. В меню загрузки (F9 или
  F12) выбирайте флешку — вариант «(UEFI)» тоже подойдёт. Если флешка не
  появилась в списке: **«Boot From EFI File»** → флешка → `EFI` → `BOOT` →
  `BOOTX64.EFI`.
* **Legacy BIOS** (старые ПК): классическая загрузка через MBR (пункт
  флешки без «(UEFI)»).

### Загрузочное меню

При загрузке с флешки (UEFI) появляется меню с выбором:

```
=====================================================
     ____   ____
    / __ \ / ___|
   | |  | | |
   | |__| | |___
    \____/ \____/
=====================================================
   OC OS 0.1 «Двухсотметровка» — ваша система

  > [1] Запустить OC                 (Enter)
    [2] Windows — основная система

   Автозагрузка OC через 5 с (стрелки — выбор, Enter — сразу)
```

Стрелки **вверх/вниз** + **Enter** выбирают пункт, цифры **1/2** — быстрый
выбор. Пункт **[2]** возвращает вас в Windows прямо из меню (ищет ваш
загрузчик Windows на дисках и передаёт ему управление). Любая клавиша
останавливает отсчёт. Esc — сразу в OC.

### Раскладка клавиатуры

* **Ctrl+Space** или **Alt+Shift** или **Ctrl+Shift** — переключить EN/RU.
  На экране появится подтверждение «раскладка: RU» / «раскладка: EN»;
* команда `раскладка` в шелле — то же самое;
* **CapsLock** — заглавные буквы.

### Звук, заставка и мышь

* `писк` / `beep` — писк динамика; `мелодия` / `song` — мотив; при старте
  OC играет короткую мелодию «до-ми-соль-до»;
* `звёзды` / `stars [N]` — заставка «Звёздное небо» (N кадров, любая
  клавиша — выход);
* в главном меню (`меню`) работает **мышь**: движение — выбор пункта,
  клик — запуск (стрелки и цифры тоже работают).

### Программы (.ocp) — и первый «браузер»!

> **Набор приложений (как в Linux/Windows!):** `calc` — калькулятор, `game` — «Угадай число», `snake` — змейка, `piano` — пианино, `wiki` — мини-браузер, `hello` — пример. Команда `programs` покажет список.

В OC уже есть **настоящие программы**: файлы формата `.ocp` крутятся в
**ring 3** (песочница), а ядро защищено от них. Запуск — набрать имя
(`wiki`, `hello`) как команду, или `пуск wiki.ocp`. Файлы смотреть —
`файлы`/`ls`, текст — `тип notes.txt`.

* **`wiki`** — мини-браузер **«Странички OC»**: страницы, ссылки-цифры,
  навигация (это первый браузер OC!);
* **`hello`** — демонстрация программы.

**Где настоящий браузер с интернетом?** Честно: для него нужны драйверы
сети (Wi-Fi), стек TCP/IP, HTTPS и движок HTML/JS — это следующие большие
ступени. Интернет в OC появится на пути: сеть → окна → браузер.

## Сборка

Нужны: `gcc` (x86_64), GNU `as`/`ld`/`objcopy`, `make`, `python3`;
для тестов, шрифта, UEFI-загрузчика и установщика —
`pip install unicorn pillow ziglang` (или они уже лежат в `.pydeps`).

```sh
make            # build/oc.img (2 MiB)
make font       # перегенерировать шрифт (DejaVuSansMono → kernel/src/font8x16.c)
make test       # смоук-тесты в эмуляторе Unicorn (28 проверок)
make run        # qemu-system-x86_64 -drive format=raw,file=build/oc.img
make run-curses # то же в текстовом окне
```

## Запись на USB-флешку

⚠️ **ВНИМАНИЕ.** `dd` пишет на устройство без вопросов и без разбора: ошибка
в имени устройства затрёт диск, в т.ч. системный. **Всегда используйте
скрипт** — он не даст выбрать не тот диск:

```sh
sudo make flash DEV=/dev/sdX
# или: sudo scripts/flash.sh build/oc.img /dev/sdX
```

Как найти свою флешку:

```sh
lsblk -o NAME,SIZE,MODEL,TRAN,MOUNTPOINT
```

Ищите строку с `TRAN=usb` и размером вашей флешки (например `/dev/sdb`).
Скрипт переспросит дважды и покажет, что именно собирается затереть.

### Windows

Скачайте `oc-v0.1.img` и запишите через **Rufus** (режим **DD Image**)
или `dd for Windows`:

* В Rufus сверху выбираете **именно флешку** (проверьте по имени и
  размеру — например «16 GB»);
* «Загрузочный диск» → «DD-образ» → укажите `oc-v0.1.img`;
* Старт. Всё.

**Не выбирайте в Rufus внешний/системный диск — программа затрёт то,
что Вы укажете.**

После записи загрузитесь с флешки (Boot Menu: обычно F12/F10/Esc при
старте; выбирайте пункт с USB).

## Возможности (ядро 0.1 «Двухсотметровка»)

- **Загрузчик**: E820 (карта памяти, до 32 записей), A20, VBE-графика
  1024×768×32 (с фолбэком на текст VGA), собственные GDT и таблицы страниц
  (идентичное отображение 0..4 GiB страницами по 2 MiB), вход в 64-битный
  Long Mode.
- **Ядро**: GDT+TSS, IDT (исключения, IRQ, `int 0x80`), PIC (ремап на
  32..47), PIT (100 Гц), физический менеджер памяти (E820, битовая карта до
  4 GiB), страничная адресация (4-уровневая, VA≠PA, `invlpg`), куча ядра
  (kmalloc/kfree), клавиатура (раскладки EN/RU, переключение **Ctrl+Space**),
  мышь (PS/2-пакеты), шрифт8×16 (DejaVu, кириллица + «№»), паника с дампом
  регистров.
- **Консоль**: дублируется в COM1 (115200 8N1) и debugcon (порт 0xE9);
  графика через VBE-фреймбуфер или текст VGA80×25.
- **Шелл** (`oc> `): помощь/help, инфо/info, память/mem, карты/mmap,
  таймер/ticks, сон/sleep, тест/ktest (стресс-тест кучи), цвет/color,
  залить/fill, мышь/mouse, раскладка/layout, вызов/sysdemo (демо `int 0x80`),
  перезагруз/reboot, стоп/halt, об/about.

## Протокол загрузчик → ядро

`struct oc_boot_info` (см. `include/boot.h`) лежит по физ. адресу `0x7000`,
указатель — в `RDI` при входе в `_start` (VMA ядра `0x100000`):

| поле | смысл |
|---|---|
| `magic` | `'COBI'` |
| `e820_count`, `e820[32]` | карта памяти (24 байта на запись) |
| `boot_drive` | номер BIOS-диска загрузки |
| `kernel_size` | размер ядра в байтах |
| `fb_*` | линейный фреймбуфер VBE (адрес, pitch, w, h, bpp, маски) |

Кодировка текста — **OC8**: `0x00–0x7F` — ASCII, `0x80–0x9F` — А..Я,
`0xA0–0xBF` — а..я, `0xC0` — Ё, `0xC1` — ё, `0xC2` — №.

## Тесты

`make test` гоняет собранный образ в Unicorn-эмуляторе (собственный
PC-харнесс в `tests/harness.py`: BIOS int 10h/13h/15h, COM1, порты PIC/PIT/
KBC/VBE): загрузчик (E820, Long Mode, A20, VBE), инициализация ядра (8
шагов), шелл (help, info, mem, ktest, sysdemo, about), перезагрузка через
порт 0xCF9 и **проверка, что ОС не пишет на диски**. Ожидаемый результат:
**28 OK, 0 FAIL**.
